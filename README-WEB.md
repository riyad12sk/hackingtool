# HackingTool Web Dashboard

A responsive public, read-only web catalog for the existing HackingTool Python project, with a private admin area, audit log, status endpoint, and a small allowlisted background worker.

## What it does

- Reads the real HackingTool engine/registry through `hackingtool.tui.data._engine`, so Python-defined tools and YAML catalog additions are represented together.
- Public catalog search by title, description, category, and tags.
- Category filtering and project links.
- Public `/api/status` and `/health` endpoints.
- Private `/admin/login` and `/admin` pages.
- Admin-only audit log and `/api/logs` endpoint.
- Background worker accepts only `catalog_audit` and `health_check` jobs.

## Safety boundary

This web application is a catalog and administration UI, not a remote hacking console. It does not expose tool install/run callbacks, shell commands, arbitrary subprocess execution, arbitrary target URLs, scanners, phishing, DDoS, RAT, or exploit execution. The worker only reads local catalog metadata and reports local app health. Keep the original CLI for local, explicitly authorized lab work.

## Local run

Python 3.10+ is required.

```bash
python -m venv .venv
. .venv/bin/activate
pip install -r requirements-web.txt
pip install .
export SECRET_KEY="replace-with-a-long-random-secret"
export ADMIN_USERNAME="admin"
export ADMIN_PASSWORD="replace-with-a-unique-strong-password"
export COOKIE_SECURE="false"  # local HTTP only; keep true on HTTPS/Render
uvicorn webapp.main:app --reload
```

Open `http://127.0.0.1:8000`. Admin: `http://127.0.0.1:8000/admin/login`.

## Deploy to Render

1. Push/merge the dashboard files into the repository's default branch.
2. In Render choose **New + → Blueprint** and select this repository.
3. Render reads `render.yaml`. During setup, enter a long, unique `ADMIN_PASSWORD` when prompted.
4. Wait for the deploy, then open the generated `onrender.com` URL.
5. Visit `/admin/login` and sign in with `admin` (or change `ADMIN_USERNAME`) and the password you supplied.

`SECRET_KEY` is generated by Render. Never commit passwords, API keys, or database URLs.

## Database persistence

The default SQLite database is `data/dashboard.db`. Render's free web service filesystem is ephemeral, so SQLite audit logs and queued jobs can be lost after a restart or redeploy. For durable records, create a managed PostgreSQL database in Render and set the web service's `DATABASE_URL` environment variable to its **Internal Database URL**. The app supports Render's `postgres://` and `postgresql://` URL forms. A paid persistent database may incur charges; check Render's current pricing before creating one.

## Worker behavior

The worker runs as a background thread inside the web service, so no second paid Render worker service is needed. It claims jobs from the database and supports only:

- `catalog_audit` — counts catalog tools/categories from local package data.
- `health_check` — reports local worker health.

The allowlist is enforced server-side. Do not add arbitrary command execution or public target scanning to this worker.

## Environment variables

| Variable | Required | Description |
|---|---|---|
| `SECRET_KEY` | Yes in production | Random secret for signed admin sessions; Render generates one from the Blueprint. |
| `ADMIN_USERNAME` | Recommended | Admin username; defaults to `admin`. |
| `ADMIN_PASSWORD` | Yes for admin login | Strong unique admin password; enter in Render Environment. |
| `DATABASE_URL` | Optional | PostgreSQL URL for durable logs/jobs; otherwise local SQLite. |
| `COOKIE_SECURE` | Optional | Secure-only session cookie; set `true` on HTTPS/Render and `false` only for local HTTP. |
| `LOG_LEVEL` | Optional | Python log level; defaults to `INFO`. |

## Endpoints

- `GET /` — public dashboard
- `GET /api/tools` — public catalog JSON; optional `q` and `category` filters
- `GET /api/status` — public status summary
- `GET /health` — Render health check
- `GET /admin/login` — admin login
- `GET /admin` — authenticated admin panel
- `GET /api/logs` — authenticated audit log JSON
